# Backend

Серверная часть проекта на `FastAPI`.

## Структура

- `app/api` — HTTP-слой и роуты.
- `app/domain` — предметная модель.
- `app/services` — прикладные сценарии.
- `app/repositories` — доступ к данным.
- `app/models` — ORM-модели.
- `app/schemas` — схемы запросов и ответов.
- `app/core` — настройки и инфраструктурные зависимости.

## Команды

Из корня проекта:

```bash
make backend-install
make backend-migrate
make backend-create-admin ADMIN_NAME="Demo Admin" ADMIN_PHONE="+7 999 000 0099"
make backend-seed-demo
make backend-dev
make backend-test
make backend-lint
make backend-typecheck
```

`make backend-seed-demo` добавляет тестовые данные для разработки и доводит набор demo-изделий до 50 штук без бесконтрольного дублирования при повторном запуске.

`make backend-create-admin` создает или обновляет администратора по номеру телефона. Пароль можно передать опционально через `ADMIN_PASSWORD`; если его не передавать, пользователь войдет через сценарий первичной установки пароля.

## API

- `GET /api/products` — список изделий.
- `GET /api/products/{id}` — просмотр одного изделия.
- `POST /api/products` — создание изделия с деревом операций.
- `DELETE /api/products/{id}` — удаление изделия.
- `PATCH /api/products/{id}/status` — смена активности изделия.

## Bitrix24

Раздел доступен только администратору. Подключение использует входящий вебхук облачного Bitrix24 с доступом `catalog`. Товары, вариации, свойства и цены загружаются по кнопке; цены Bitrix не изменяют расценки Flowcraft

- Применить миграцию `20261112_0039` перед использованием раздела
- Сохранить базовый HTTPS URL вебхука через интерфейс Bitrix24 в Flowcraft
- При необходимости задать `BITRIX_KEY_PATH` в серверном окружении до первого сохранения
- По умолчанию использовать `apps/backend/.secrets/bitrix.key`: ключ создаётся автоматически с правами `0600`
- Сохранять ключ при обновлении сервера и резервировать отдельно от БД; для восстановления подключения нужны и БД, и соответствующий ключ
- Не помещать ключ и URL вебхука в Git или журналы
- При утрате ключа заново сохранить вебхук того же портала

Секрет хранится в БД в зашифрованном виде и не возвращается через API. Замена вебхука того же портала поддерживается, смена портала запрещена для защиты существующих сопоставлений

Обновление запускается в фоне, результат публикуется одной транзакцией. При ошибке предыдущие товары и цены сохраняются. После аварийного завершения процесса повторный запуск доступен через 15 минут. Автоматическая подписка на события Bitrix и импорт сделок в этой версии не реализованы

### Стоимость операций

Базовая ставка задаётся в настройках расчёта (начальное значение — 350 ₽/час).
Стоимость операции: БС × коэффициент × время на изделие / 3600,
с округлением вверх до копейки. Ручная норма времени имеет приоритет над статистикой. При отсутствии обоих
значений стоимость равна нулю. При изменении времени цена сразу обновляется
в форме и сохраняется вместе с изменениями изделия.
Коэффициент хранится целым числом в масштабе 10 000 и отображается с четырьмя
знаками после запятой. Отчёты выполненной работы используют текущие расценки.

Миграция 0043 вызывает `scripts/migrate_operation_pricing.py` и сохраняет прежние
цены, полученные коэффициенты и отклонения в `operation_price_migration_report`.
Для коэффициента при переносе используется округление до ближайшего значения
с четырьмя знаками, для итоговой цены — вверх до копейки.
Чтобы выгрузить сохранённый отчёт SQLite в CSV, выполнить из `apps/backend`:

```bash
.venv/bin/python scripts/migrate_operation_pricing.py flowcraft.db /tmp/operation-pricing-migration.csv
```
