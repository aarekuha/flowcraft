# Журнал изменений

## 0.8 - 2026-06-08

### Добавлено

- Добавлен справочник `Операции`, размещенный первым в списке справочников конструктора.
- Названия конечных операций в изделиях теперь выбираются из справочника операций с поиском по вводу и сортировкой по алфавиту.
- Добавлена миграция справочника операций: текущие уникальные названия конечных операций переносятся в справочник, а операции изделий связываются с ним через идентификатор.
- Для справочника операций добавлена уникальность поля `name`.
- Для назначений исполнителей добавлены статусы `В работе`, `Скрытые` и `Выполненные` с хранением состояния по конкретному исполнителю и операции.
- На вкладке исполнителя добавлен выпадающий фильтр отображения операций: `В работе`, `Скрытые`, `Выполненные`.
- При переносе операции исполнителя в скрытые или выполненные добавлено подтверждение действия.

### Изменено

- Скрытие у исполнителя перенесено с уровня заказа на уровень конкретной назначенной операции.
- Если скрываемая или завершаемая операция была активным таймером, таймер операции переключается на `Перерыв`.
- В бригадире сортировки перенесены в заголовки таблиц: повторный клик меняет направление сортировки.
- Сортировки по версии, исполнителям и суммарному времени у бригадира убраны.
- В создании заказа поле `Вид кожи` теперь работает как автодополнение по справочнику.
- Выбор исполнителя в модалке бригадира возвращен к редактируемому полю с фильтрацией списка по вводу.
- Группы операций в конструкторе изделия вводятся вручную и не требуют выбора из справочника операций.

### Ограничения

- Запуск таймера для скрытых и выполненных операций запрещен на frontend и backend.
- Конечные операции в конструкторе можно использовать только из справочника операций.
- Значения справочника операций нельзя удалить; неактивные значения можно скрывать из выбора.
- Конечная операция остается уникальной в рамках изделия по идентификатору операции из справочника.

### Исправлено

- Исправлено смещение выпадающих списков на мобильных экранах.
- Исправлена цепочка миграций после обновления `development`: добавлена единая голова поверх `20260603_0011`.
- Auth middleware переведен на прямой ASGI middleware, чтобы избежать зависаний `TestClient` и повторных сессий вокруг запроса.

## 0.7 - 2026-06-03

### Добавлено

- На странице исполнителя у заказа добавлена галочка `Скрыть`.
- Над списком заказов исполнителя добавлены чекбокс `Показывать скрытые` и счетчик скрытых позиций.
- Добавлено персональное хранение видимости заказа для текущего пользователя через таблицу `user_work_order_visibility`.
- Добавлен backend-эндпоинт `PATCH /api/orders/{order_id}/visibility`, который обновляет видимость заказа для пользователя из текущей сессии.
- `GET /api/orders/worker-assignments` теперь возвращает список назначений исполнителя вместе со счетчиком скрытых позиций и поддерживает параметр `include_hidden`.

### Ограничения

- Пользователь может скрывать только активные заказы, назначенные ему как исполнителю.
- Скрытие не меняет статус заказа и не влияет на видимость заказа для других пользователей.

## 0.6 - 2026-06-01

### Изменено

- Цена теперь задается только для конечных операций изделия; группы операций не имеют цены.
- В карточке уже созданного изделия цены операций доступны только для просмотра, редактировать можно только стоимость материала.
- При добавлении дочерней операции цена родительской группы автоматически очищается.
- В таблицах заказов уточнено отображение временных полей: во вкладке `В работе` скрыто время выполнения, во вкладке `Созданные` скрыты время взятия в работу и время выполнения.
- Поле `Время проведения ОТК` во вкладке `Выполненные` теперь показывает момент проведения ОТК, а не длительность между передачей в ОТК и завершением.

### Ограничения

- Backend запрещает создание группы операций с ценой.
- Backend запрещает изменение цен операций у уже созданных изделий.
- Изменение вида кожи и количества изделий заказа разрешено только пока по заказу нет потраченного времени.
- Проверка потраченного времени выполняется по фактическим operation-таймерам, включая активные таймеры и интервалы меньше минуты, а не по округленному счетчику минут.
- Назначения исполнителей можно изменять до передачи заказа в ОТК.
- На стадии `ОТК`, у выполненных и удаленных заказов назначения исполнителей недоступны для изменения.
- Удаленные заказы в модальном окне доступны только для просмотра, без редактирования и без кнопки сохранения.

### Исправлено

- Исправлена возможность редактировать удаленные заказы через интерфейс.
- Исправлена возможность изменять исполнителей после передачи заказа в ОТК.
- Исправлена невозможность выбрать другого исполнителя у существующего заказа: выпадающий список больше не фильтруется текущим полным именем исполнителя.
- Исправлена невозможность изменить количество изделий у заказа без потраченного времени.
- Добавлена миграция очистки старых цен у групп операций.

### Bugfix

- Исправлена ошибка входа пользователя с ролью `ОТК`: backend-схема ролей теперь поддерживает значение `quality_control`.
- Исправлено отображение статуса пользователя в разделе `Пользователи и доступы`: текст внутри бейджа активности центрируется.

## 0.5 - 2026-06-01

### Добавлено

- Добавлена роль `ОТК` для контроля качества заказов.
- Добавлен новый этап жизненного цикла заказа `ОТК` между состояниями `В работе` и `Выполненные`.
- Добавлена вкладка `ОТК` в управлении заказами с колонками номера заказа, наименования, вида кожи, версии и даты передачи в ОТК.
- Добавлены действия `Передать в ОТК`, `Принять`, `Вернуть в работу` и `Вернуть на ОТК`.
- Добавлена приемка заказа через модальное окно ОТК с указанием количества брака.
- Добавлено хранение даты передачи в ОТК и количества брака в заказе.
- Во вкладке `Выполненные` добавлены колонки `Время проведения ОТК` и `Количество брака`.
- Добавлена детализация суммарного времени заказа по клику: операция, исполнитель, время и итог.
- В конструкторе изделия добавлена стоимость материала.
- Для операций изделия добавлена необязательная цена.
- Добавлена отдельная кнопка сохранения стоимости материала и цен операций.
- Добавлены миграции для стоимости изделий и данных ОТК.

### Изменено

- Действие `Выполнен` во вкладке `В работе` заменено на `Передать в ОТК`.
- Завершение заказа теперь выполняется через приемку ОТК, а не прямым изменением статуса выполнения.
- Выполненный заказ возвращается не сразу в работу, а на вкладку `ОТК`.
- Заказы, переданные в ОТК, больше не отображаются у исполнителей в таймерах.
- Количество изделий заказа после создания больше нельзя изменить.
- Поле количества брака в приемке ОТК сделано числовым, с фокусом при открытии окна.
- Иконка вкладки `ОТК` заменена на лупу, иконка `Выполненные` - на галочку.
- Табы управления заказами адаптированы для ширины экрана `761px`-`995px`.

### Безопасность

- Проверка прав на приемку ОТК теперь выполняется на backend по актуальным ролям пользователя, а не по снимку ролей в активной сессии.
- Если у пользователя забрали роль `ОТК`, операция приемки становится недоступной сразу, без повторного входа.

### Исправлено

- Исправлена возможность принять заказ в ОТК после удаления роли `ОТК` у текущего пользователя.
- Исправлено некорректное отображение строки табов управления заказами на промежуточной ширине экрана.

## 0.4 - 2026-06-01

### Добавлено

- Жизненный цикл заказов у бригадира разделен на состояния `Созданные`, `В работе`, `Выполненные` и `Удаленные`.
- Заказ после создания больше не берется в работу автоматически и не отображается у исполнителей, пока бригадир явно не нажмет `Взять в работу`.
- Добавлены действия для управления жизненным циклом заказа: `Взять в работу`, `Выполнен`, `Вернуть в работу`, `Вернуть в созданные`, `Удалить` и `Восстановить`.
- Добавлены подтверждения перед изменяющими действиями с заказами: возвратом, удалением, восстановлением и завершением.
- Для заказов добавлено отдельное поле оценки трудозатрат, которое хранится отдельно от фактически накопленного времени.
- Добавлена backfill-миграция для пересчета накопленного времени заказов по уже закрытым таймерам операций.
- Добавлена возможность сохранять создаваемый или редактируемый заказ без указания исполнителей операций; в печатной форме такие исполнители выводятся пустыми полями.

### Изменено

- Вкладка `Новый заказ` у бригадира перенесена первой.
- Вкладки состояний заказов у бригадира вынесены на один уровень с вкладкой `Новый заказ`, без вложенных табов внутри управления заказами.
- Фильтрация заказов по статусу выполнения заменена отдельными вкладками состояний.
- Действия в таблицах приведены к единому виду: список ссылок с иконками вместо набора разных кнопок в одну строку.
- Загрузка списка заказов бригадира отделена от загрузки заказов исполнителя, чтобы не выполнять лишние запросы к `/api/orders`.
- В разделе `Конструктор -> Изделия и дерево операций` действие просмотра показывает количество этапов в формате `Просмотр (N этапов)`.
- Карточка изделия в конструкторе открывается при клике по наименованию изделия.
- В таблицах конструктора и справочников колонки управления приведены к общему формату `Действия`.
- В разделе `Пользователи и доступы` деактивация перенесена в колонку `Действия`.

### Исправлено

- Исправлен пересчет суммарного времени заказа при закрытии таймера операции: перед агрегирующим запросом backend фиксирует изменения текущей сессии.
- Суммарное время в заказах у бригадира теперь согласовано со статистикой трудозатрат и учитывает уже закрытые таймеры операций.

## 0.3 - 2026-05-31

### Добавлено

- Кнопка `Печать` в колонке действий заказов в разделе `Бригадир -> Управление заказами -> В работе`.
- Печатная форма заказа с простой таблицей: изделие с версией, тип кожи, количество и список операций с исполнителями.

## 0.2 - 2026-05-31

### Добавлено

- Раздел `Конструктор -> Справочники` с вложенным справочником `Виды кожи`.
- Создание, активация и деактивация видов кожи без возможности полного удаления или редактирования наименования.
- Backend-эндпоинты `GET /api/leather-types`, `POST /api/leather-types` и `PATCH /api/leather-types/{leather_type_id}/status`.
- Таблица `leather_types` и связь заказа с видом кожи через `work_orders.leather_type_id`.
- Поиск, сортировка и пагинация справочника видов кожи на backend.
- Выбор вида кожи при создании и редактировании заказа в работе у бригадира.
- Колонка `Вид кожи` в таблице `Бригадир -> Управление заказами -> В работе`.
- Отображение вида кожи в заголовке назначений исполнителя рядом с количеством изделий.

### Изменено

- Основной экран конструктора разделен на табы `Изделия и дерево операций` и `Справочники`.

- Группировка назначений исполнителя учитывает вид кожи, чтобы одинаковые изделия с разной кожей не объединялись.
- При отсутствии выбранного вида кожи интерфейс показывает текст `вид кожи не указан`.

### Ограничения доступа

- Создавать и менять активность видов кожи могут пользователи с ролью `constructor` или `admin`.

## 0.1 - 2026-05-30

### Добавлено

- Учет выполнения заказов через поле `completed_at`.
- Backend-эндпоинт `PATCH /api/orders/{order_id}/status`, который отмечает заказ выполненным или возвращает его в работу.
- Действия бригадира для заказов: `Выполнен` и `Вернуть в работу`.
- Галочка `Показывать выполненные` в разделе `Бригадир -> Управление заказами -> В работе`; по умолчанию выполненные заказы скрыты.
- Поиск заказов на стороне backend по номеру заказа и наименованию изделия.
- Сортировка заказов на стороне backend по дате создания, дате выполнения и наименованию изделия.
- Пагинация для `GET /api/orders` с полями `page`, `page_size`, `total` и `pages`.
- Колонки `Время взятия в работу` и `Время выполнения` в таблице заказов в работе.
- Изменение количества изделий у уже существующего заказа в работе.
- Диалог подтверждения перед созданием или сохранением заказа.

### Изменено

- `GET /api/orders` теперь возвращает страницу данных вместо простого массива.
- Фильтрация и сортировка заказов в работе выполняются на backend, а не на frontend.
- Таймеры исполнителя отдельно загружают все активные заказы, поэтому не зависят от пагинации таблицы бригадира.
- Поиск заказов применяется только после нажатия `Enter`; ввод текста больше не перезагружает список на каждый символ.

### Исправлено

- Поиск заказов больше не зависит от регистра, включая наименования изделий на кириллице.
- Убрано дублирование заказов на вкладке бригадира: мобильные карточки скрываются, когда отображается desktop-таблица.
- При возврате заказа в работу время выполнения очищается.
